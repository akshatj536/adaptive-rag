## What this says

**The current configuration is the slow one.** `gemini-3.6-flash` takes 8.74s
on a RAG-sized prompt — roughly **8x** slower than `groq/gpt-oss-20b` (0.86s),
`mistral-small` (0.97s) or `gemini-3.5-flash-lite` (1.12s). That single choice
dominates end-to-end latency, since generation runs on every query.

**Reasoning tokens are the hidden tax.** For an identical one-line
classification, `gpt-oss-20b` emits 238 tokens (217 of them hidden reasoning)
while `ministral-8b` emits 27 and `llama-3.1-8b-instruct` emits 16. Same answer,
**~15x** the tokens. Non-reasoning instruct models are strictly better for
routing.

**Avoid qwen for structured output.** It emits `<think>` blocks that break JSON
parsing, which the classifier and the agentic grader both depend on.

## Suggested role assignments

| Role | Model | Why |
|---|---|---|
| `routing` | `mistral/ministral-8b-latest` | fastest, no reasoning tax, valid JSON |
| `reasoning` | `groq/openai/gpt-oss-120b` | strong, 0.69s, modest reasoning |
| `generation` | `mistral/mistral-small-latest` or `gemini/gemini-3.5-flash-lite` | ~1s on RAG prompts vs 8.7s |

Fallbacks should span providers: pairing Mistral with Groq or NIM means a
Mistral outage doesn't stall anything.

## Gotchas

- **Cerebras free tier is not free on this account.** The published 1M
  tokens/day requires billing to be enabled. Treat published free-tier claims
  as unverified until a call succeeds.
- **NIM lists more than it serves.** `mistral-7b-instruct-v0.3` 404s and
  `llama-3.3-70b-instruct` times out, both while appearing in `/v1/models`.
- **NIM has no cost data** in LiteLLM's map (3 entries, all rerankers), so cost
  tracking needs explicit `input_cost_per_token` / `output_cost_per_token`.
  `ministral-3b` also returned no cost.
- **Several models wrap JSON in ```json fences** (`ministral-3b`,
  `gemini-3.6-flash`, `gemini-3.5-flash-lite`). The existing parser already
  strips these; keep that behaviour if the parser is ever rewritten.
